# Удаление менеджера

Команда удаляет Telegram-бота и Mini App с сервера, сохраняя возможность восстановления. VPN-контейнеры и конфиги на подключённых VPN-серверах продолжают работать.

## Удалить одной командой

Запустите в интерактивном SSH-терминале VPS, где установлен менеджер. Нужен `curl` и root либо `sudo`.

```bash
bash -c 'set -e; task_script=$(mktemp); trap "rm -f -- \"$task_script\"" EXIT; curl -fsSL https://raw.githubusercontent.com/wickedslim/amnezia-vpn-manager/main/uninstall.sh -o "$task_script"; if [ "$EUID" -eq 0 ]; then bash "$task_script"; else sudo bash "$task_script"; fi'
```

Скрипт покажет службу и каталог и попросит подтвердить удаление. Для нестандартной установки задайте `AWG_SERVICE_NAME` и `AWG_INSTALL_DIR` при ручном запуске.

Из скачанного проекта:

```bash
sudo bash uninstall.sh --check
sudo bash uninstall.sh
```

`--check` проверяет установку и показывает план без изменений. Старый awg-docker-bot без структуры нового менеджера автоматически не удаляется.

## Что происходит

- Проверяются служба, рабочий каталог и запускаемый файл. Пересечение каталога с Docker mount отменяет удаление; работающий процесс обновления также блокирует его.
- Служба бота останавливается и отключается от автозапуска.
- Каталог установки целиком, включая базу, настройки, сохранённые конфиги и окружения Python, переносится в `/var/backups/amnezia-manager/uninstall-ДАТА-PID/installation`. Туда же сохраняются systemd unit и его drop-in-файлы. Доступ к папке — только root.
- Выделенный Caddy отключается только при точном совпадении его конфигурации с шаблоном нашего установщика. Общий или изменённый Caddyfile остаётся без изменений; удалите только маршрут Mini App вручную. Пакет Caddy и сертификаты не удаляются.
- Системные пакеты, Docker, AmneziaWG, прежние резервные копии и приватные журналы обновлений не удаляются. Резервная копия сохраняет место на диске; это удаление установленного сервиса, а не безвозвратная очистка всех данных.

Файл резервной копии содержит секреты. Не публикуйте и не пересылайте его. Пока бот удалён, лимиты/сроки клиентов и новые уведомления не обрабатываются; уже применённые VPN-настройки остаются.

## Восстановление

В итоговом сообщении будет полный путь к резервной папке. В ней лежат `original-path.txt`, `service-name.txt`, `installation`, `manager.service` и, при наличии, `drop-ins` и `Caddyfile`.

1. Прочитайте исходные путь и имя службы. Убедитесь, что новая установка не занимает этот путь.
2. Перенесите `installation` на исходное место, `manager.service` — в `/etc/systemd/system/ИМЯ.service`, `drop-ins` — в `/etc/systemd/system/ИМЯ.service.d`.
3. Выполните `systemctl daemon-reload` и `systemctl enable --now ИМЯ`.
4. Если был отключён выделенный Caddy, восстановите его Caddyfile, проверьте `caddy validate` и включите `systemctl enable --now caddy`. Не заменяйте конфигурацию другого сайта.

VPN-контейнеры для восстановления бота перезапускать не нужно.

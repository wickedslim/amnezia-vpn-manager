# Перенос менеджера и AmneziaWG на новый VPS

Команды ниже входят в `2.0.0-beta.9`.

## Подготовка

- Новый VPS: Ubuntu 24.04 либо Debian 12, root-доступ по SSH, свободные VPN-порты. На нём не должно быть переносимого контейнера, службы менеджера и её каталога. Для Mini App также нужны свободные TCP-порты 80 и 443.
- Запускайте команду на старом VPS через SSH или веб-консоль хостера, если входящий SSH либо Mini App недоступны. Старому VPS требуется исходящий SSH к новому VPS. Для подключения используются root-пароль нового VPS или SSH-ключ.
- В конфигурациях клиентов заранее используйте домен вместо IP. При переезде ключи и порт сохраняются; IP в DNS нужно заменить вручную. Уже выданные конфигурации с IP сами не изменятся.
- Сохраните свежий ZIP-бэкап отдельно от старого VPS. Полный перенос копирует также токен бота, настройки и сертификаты — защищайте доступ к обоим серверам.

## Перенос из Mini App

Владелец открывает карточку VPS, на котором работает бот, и выбирает «Управление сервером → Перенос сервера». Укажите IP нового VPS и SSH-порт. После проверки подтвердите запуск. До проверки настройте со старого VPS вход под root по SSH-ключу и добавьте проверенный ключ нового хоста в `known_hosts` пользователя root на старом VPS.

Перенос выполняется отдельной службой systemd и продолжится, даже если Mini App потеряет связь. Ход переноса можно проверить через `sudo journalctl -u awg-manager-move -f` в консоли старого VPS. DNS переключайте после завершения.

## Проверка и перенос

```bash
sudo awg-move НОВЫЙ_IP --check
sudo awg-move НОВЫЙ_IP
# Если SSH на нестандартном порту:
sudo awg-move НОВЫЙ_IP:2222
```

`--check` проверяет доступность и конфликты. Бот, VPN и данные не меняются; SSH может сохранить ключ нового хоста в `known_hosts`. Обычный запуск покажет план и попросит ввести `yes`. Флаг `--yes` пропускает это подтверждение.

Если `awg-move` ещё не установлен, скачайте исходники опубликованного релиза на **старый VPS** в отдельный каталог. Команда из исходников переносит установленную на старом VPS версию менеджера. Для примера замените `203.0.113.10` на IP нового VPS.

```bash
move_source=$(mktemp -d)
git clone --depth 1 --branch v2.0.0-beta.9 https://github.com/wickedslim/amnezia-vpn-manager.git "$move_source"
sudo bash "$move_source/scripts/awg-move.sh" 203.0.113.10 --check
sudo bash "$move_source/scripts/awg-move.sh" 203.0.113.10
```

Сначала копируются Docker-образ, файлы VPN, код менеджера, systemd units, выделенный Caddy с сертификатами и сборщик трафика. Старый бот продолжает работать во время подготовки. Затем он останавливается, копируются актуальные клиенты и база, запускается новый бот. При ошибке переключения скрипт пытается остановить новый экземпляр и вернуть старый. Проверьте итоговые состояния служб, если SSH-соединение оборвалось.

После успешного переноса:

1. Измените DNS-записи VPN и Mini App на новый IP.
2. Проверьте доступность панели, бота и подключение клиентов. Некоторые устройства разрешают имя сервера только при запуске туннеля: для них понадобится повторное подключение или отдельная проверка механизма обновления DNS.
3. Убедитесь, что старый бот отключён, а новый работает: `systemctl status awg_bot`. Два экземпляра с одним Telegram-токеном запускать нельзя.
4. Старый VPN оставьте до перехода клиентов на новый адрес. Сам скрипт его не останавливает.

Если подготовка прервана, старый бот и VPN остаются на месте. На новом VPS могут остаться пакеты, контейнер и файлы. Перед повтором проверьте их либо заново подготовьте чистый VPS. При занятом `apt` скрипт ожидает освобождения блокировки до двух минут; ошибка установки пакетов останавливает перенос до переключения.

Проверенный сценарий — стандартный контейнер AmneziaWG с bridge-сетью и одинаковая архитектура x86_64. Нестандартные mounts, переопределённые команды контейнера, общие HTTPS-прокси и другая архитектура требуют отдельной проверки. Вынесенный через `AWG_DATA_DIR` каталог данных не поддерживается автоматическим переносом.

Если для управления удалёнными VPN-серверами используются SSH-ключи вне каталога менеджера, перенесите их отдельно с сохранением путей и прав. Автоматически копируется каталог менеджера, а не весь домашний каталог root.

## VPN без приложения AmneziaVPN

```bash
sudo awg-vpn install --port 42080 --subnet 10.87.0.0/24
sudo awg-vpn status
```

Устанавливается стандартный контейнер `amnezia-awg`. Затем добавьте его в менеджере. Новый VPN получает новые ключи и параметры обфускации; для сохранения существующих клиентов используйте перенос или восстановление.

## Если старый VPS потерян

```bash
sudo awg-vpn restore /закрытый/путь/backup.zip
```

Восстанавливается VPN из `server/wg0.conf` и `server/clientsTable` в ZIP-бэкапе менеджера. Порт должен быть свободен; контейнер с выбранным именем не должен существовать. После запуска направьте VPN-домен на новый IP.

Эта команда восстанавливает VPN. Автоматическое полное восстановление менеджера, его токена, сертификатов и базы отдельной командой пока не реализовано. В ZIP есть `manager.sqlite3`, но токен и сертификаты нужно хранить отдельно. Приостановленные клиенты находятся в базе менеджера и не добавляются в активный VPN одним восстановлением `wg0.conf`.

Режим выдачи новых конфигов меняется владельцем в Mini App: сервер → «Управление сервером» → «Выдача конфигов · IP / DNS». Оба адреса сохраняются в базе. При переезде сохранённый IP локального сервера обновляется на новый, выбранный домен сохраняется. DNS-запись у провайдера меняется отдельно; ранее выданные конфиги с IP автоматически не заменяются.

Если для VPN заданы дополнительные IP, проверьте их доступность после переезда. Скрипт меняет сохранённый основной IP на адрес нового VPS. Дополнительные IP проверьте и обновите в списке адресов выдачи. Уже выданные конфиги при этом не переписываются.
